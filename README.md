# 陶艺展览策划台

面向独立策展人的 Vue 3 展览编排工具。首屏直接进入策展工作面：创建展览草稿、选择作品并上线展览状态。

## 使用

```bash
npm install
npm run dev
npm run build
```

数据保存在浏览器 `pottery-exhibit-studio-v1` 命名空间。当前为初始化基线，测试将在后续任务中补充；构建命令覆盖三个工作流的生产烟囱检查。

## 本地质量检查（npm run check）

`npm run check` 是统一的本地质量检查入口，依次执行两个步骤，任一步失败立即终止并返回明确的非零退出码：

```bash
npm run check
```

| 顺序 | 步骤 | 实际执行 | 检查内容 | 失败退出码 |
| ---- | ---- | -------- | -------- | ---------- |
| 1 | Vue/TS 类型检查 | `vue-tsc -b` | 对 `<script setup lang="ts">` 及全部 TypeScript 做类型检查（含 Vue SFC 模板类型），不产出构建物 | `10` |
| 2 | 产物构建 | `vite build` | 打包生产产物到 `dist/`（转译、依赖打包、资源处理） | `20` |

全部通过退出码为 `0`；参数用法错误（未知参数、同时跳过两步等）退出码为 `1`。

查看退出码：

```bash
npm run check
echo $?   # 0 / 10 / 20 / 1
```

### 单独跳过某一步

通过 `--skip <步骤名>` 跳过对应步骤（`--` 用于把参数透传给检查脚本）：

```bash
# 只做类型检查，跳过产物构建（失败码 10）
npm run check -- --skip build

# 只做产物构建，跳过类型检查（失败码 20）
npm run check -- --skip typecheck
```

两步不能同时跳过。跳过只影响本次 `check`，不会修改任何配置。

### 单独运行某一步

也可以不经过统一入口，直接运行单个步骤，便于快速定位：

```bash
npm run typecheck   # 仅类型检查（vue-tsc -b）
npm run build       # 对外构建命令，行为不变：先 vue-tsc -b 再 vite build
```

说明：`npm run build` 仍保持原有行为（内部自带一次类型检查），供部署/CI 等外部调用方使用；`npm run check` 把类型检查与构建拆成两个独立步骤执行，因此失败时可以凭输出分段和退出码区分是类型问题还是打包问题。

测试按初始化基线约定延后，当前没有测试框架，`check` 不包含也不会伪造任何测试步骤；所有检查均在本地执行，不访问网络、不引入额外依赖。
